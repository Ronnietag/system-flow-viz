# 设计树提问清单
> 🇬🇧 **English readers**: this reference is the Chinese edition; the bilingual
> `README.md` in the repository root summarises the same contract and rules.

按轮次问。**每轮只问「前置决策已定」的那批**；每题给推荐答案，让用户回「是」即可。
**别问「能不能做」**——那是你的活。**别问「事实是什么」**——事实是你的活，派子代理去查。

## 第 1 轮（决定形态）

**Q1 受众与术语层级**：这个可视化主要给谁看？
- A 两者兼顾：默认业务语言，点开展开见代码细节（推荐）
- B 纯开发者视角
- C 纯业务视角

**Q2 覆盖范围**：画到哪一层？
- A 平台全部功能全画，无死角（用户强调「每一步都不许漏」时选这个）
- B 主链路深挖 + 其余功能成侧枝挂载
- C 只画主链路

**Q3 载体形态**：
- A **React 组件** + 顶栏多视图切换（推荐；**交互必需时选它**）
- B 静态 HTML 单文件（**只能看，不能交互** —— 悬停高亮/点开钻取都做不了）
- C 图片/文档（只要一张示意图时）

⚠️ **2026-11-05**：原本推荐「单文件 HTML」⇒ 已改。
   静态图做不了交互，而可视化恰恰是为了交互（悬停看细节、点开看来源）⇒
   **默认 A**；B 只在用户明确要「能发给别人看的单文件」时选。

**Q4 图形形式**：
- A 分层流程图（可切换思维导图）（推荐）
- B 纯 Visio 式流程图
- C 纯思维导图

**Q5 准确性标准**：
- A 源码行号 + 实测只读库表结构（需允许跑只读脚本）（推荐）
- B 只标源码行号，不连库
- C 以现有文档口径为准

**Q6 是否沉淀成 skill**：
- A 通用 skill，装到通用技能目录 + 各工具目录（推荐）
- B 只装当前工具目录
- C 放项目内，只对本项目生效

## 第 2 轮（决定内容与交互）

**Q7 视图（页签）怎么切**：给三套切法让选（4 视图 / 6 视图 / 8 视图）。

**Q8 节点详情固定几块**：给骨架让选（固定 6 块 / 固定 7 块 / 固定 7 块+源码片段可复制）。

**Q9 交互深度**：点开详情 / +搜索筛选+折叠分层 / +反向查找（给定表或字段列出所有用到它的节点）。

**Q10 归档物算不算运行节点**：全进图但样式区分 / 只画现行运维脚本 / 不画归档物。

**Q11 落盘位置与要不要提交 git**：
- A 落盘到 `docs/<feature>/`，**不提交 git**（推荐，交由用户自行审阅）
- B 落盘并建分支提交
- C 另开独立目录

**Q12 skill 形态**：
- A name+description+流程正文+校验清单（+事实采集脚本）（推荐）
- B 精简版（只有流程正文）
- C 完整版 + HTML 页面模板文件

## 第 3 轮（决定数据组织与验证）

**Q13 节点数据怎么存**：
- A **TS 常量清单**（`NODES` / `LINKS`）+ 组件 import 它（推荐；改平台时只改清单）
- B `nodes.json` + 组件读 JSON（清单与组件分离，但多一次构建）
- C 数据从只读接口实时拉（清单不落盘 ⇒ 每次都要有服务在跑）

⚠️ **共同点**：**清单与组件必须分开** ⇒ 组件只管「怎么画」，不管「画什么」。

**Q14 文档与代码冲突怎么处理**：
- A 在节点里显式标 ⚠（文档说 X / 代码是 Y / 出处）（推荐）
- B 只写代码事实
- C 冲突集中到勘误附录

**Q15 图上带不带真实数据**：
- A 全带 + 标注实测时间（推荐）
- B 带行数不带取值样例
- C 纯结构

**Q16 思维导图与流程图的关系**：
- A 同源同粒度，一键切换（推荐）
- B 思维导图只做导航索引

**Q17 要不要加「运行阶段时间轴」视图**：加（9 视图）/ 不加（折进总览）。

**Q18 视觉与打印**：浅/深色跟随系统 + 打印友好（推荐）/ 只浅色 / 只深色。

**Q19 测试缝**（先讲清本项目不设自动化测试时怎么验）：
- A 三条缝：**类型与构建** + **引用校验器** + **真实环境取证**（推荐）
- B 只要类型与构建 + 真实环境取证
- C 三条缝 + 组件快照回归

⚠️ **2026-11-05**：原第一条是「生成器出口」⇒ 改成「类型与构建」
   （`tsc --noEmit` + 构建命令）—— 没有生成器了。
   ⚠️ 校验器必须**独立可运行、退出码非零即失败**（才能进发布闸门）。

**Q20 取证缺口要不要补齐**：全补 / 只补关键几项 / 不补（在页面里声明未取证）。

**Q21 真实取证强度**：起真实服务 + 冒烟 + 浏览器逐页截图 / 只跑冒烟 / 不起服务。

**Q22 发现的真 bug 怎么处理**：
- A 只记录：页面 ⚠ 标注 + 另开工单，不改业务代码（推荐）
- B 本轮一并修
- C 只标注不开单

**Q23 仓库可发现性**：只加 `docs/<feature>/README.md` / 顺带改根 README / README + AGENTS.md 都改。

## 使用要点

- 每题给推荐答案，且推荐项写「yes 即采纳」
- 用户回答后重算前沿，把新解锁的问题放进下一轮
- **前沿清空且用户确认后**才开始动手写规格
- 决策点用选择工具给选项，不要替用户做不可逆决定
